# 2026-07-18 リポジトリ立ち上げ

マルチテナント社内精算・ウォレット基盤デモの公開リポジトリを立ち上げた。
立ち上げの意思決定はすべて人間が最終判断し、AI は候補生成と実務を担った。

## 名前選定

リポジトリ名 = プロダクト名 = 連載名として使える名前を、4 案の比較で決めた。

- 候補軸: 造語合成（Settledger）/ 英単語合成（SettleBase）/ 日本語ドメイン語（Daicho）/ テーマ直結（WalletFence）
- 全候補に衝突 3 点確認（GitHub リポジトリ・npm・一般 Web 検索）を実施。
  初期候補 2 つ（Tenlet・Tatekae）は既存プロダクトとの衝突・密集で候補提示前に差し替えた
- **採用: SettleBase**（理由: シンプル）。settle（精算）+ base（基盤）で、技術スタックの Supabase と韻を踏む
- 既知の同名: settlebase.io（2022 年の個人開発の予約管理 MVP・分野違い小規模）を認識した上で採用

## 構成の赤入れ

ディレクトリレイアウト + README 骨子の 1 案を人間に提示し、赤入れを 2 往復して確定した。

- v1（テンプレを repo 直下に展開）への赤入れ: アプリ都合のファイルと docs・ツールが
  同列に並ぶと把握しづらい → **アプリを `web/` に隔離し repo 直下を並列構成に**（v2 で確定）
- 確定事項: README は日本語のみ / devlog は `YYYY-MM-DD-topic.md` /
  `tools/` は必要になった時に作成し、`web/` と独立したスタックを選べる /
  workspace 管理は入れない
- 詳細は [ADR-0001](../adr/0001-repo-layout.md)

## スタックの再検討

赤入れの中で「Next.js を使うか、バックエンドに Ruby を使うか再検討したい」という
論点が出た。検討の結果、**計画どおり Next.js + Supabase + Vercel を維持**した。

- 理由: このデモの核（Postgres RLS・認可テスト・開発ハーネス）はフレームワーク非依存で、
  フレームワークは土台にすぎない。無料枠で公開 URL まで最短で到達できる構成を優先
- 別スタックへの興味は `tools/` の「web と独立したスタック可」という方針で受けた

## scaffold と公開

- 公式 with-supabase テンプレ（cookie ベース Auth・supabase-ssr）を `web/` に scaffold
- README（Problem / Solution / Out of Scope）・LICENSE(MIT)・docs 骨格を追加
- [公開前の境界チェック](2026-07-18-boundary-check.md) を通過してから
  GitHub リポジトリを作成し push（公開はゲート通過後の 1 回のみ）
