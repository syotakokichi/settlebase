# 画面要件仕様（screen-specs）

主要 6 画面の UI 設計に先立つ要件仕様。各画面に「必須要素チェックリスト」を持ち、
ワイヤー完成時にこのチェックリストとの適合を確認する（結果は devlog に記録）。
用語は [GLOSSARY](../../GLOSSARY.md) に従う。デザイントークンは
[design-system.md](design-system.md) を参照。
2026-07-20 赤入れ確認で確定（ロールモデル 4 種 / 共通シェル構成 / 設計判断①〜④ /
ワイヤー深さ、いずれも原案どおり）。

## 前提: ロールモデル（本仕様で定義する目標形）

現行スキーマは tenants / members / wallets のロールなし最小形。UI 設計では以下の
4 ロールを目標形として定義し、実装は後続で追随する。

| ロール | できること | できないこと |
| --- | --- | --- |
| 申請者（maker） | 振替・立替精算の申請作成、自分の申請の取り下げ | 承認、自分の申請の自己承認 |
| 承認者（checker） | 申請の承認・却下 | 自分が作成した申請の承認（maker-checker 分離） |
| 管理者（admin） | ロール付与・変更、ウォレット作成 | 台帳エントリの編集・削除（append-only は誰でも不可） |
| 監査（viewer） | 台帳・監査ログの閲覧 | 一切の作成・変更操作 |

## 業務フロー・記帳モデル（2026-07-20 確定）

6 画面が 1 つの物語として矛盾しないための要件レベルの決定。

| 論点 | 決定 |
| --- | --- |
| ウォレットの持ち主 | 部門に加えて**メンバー個人のウォレットも存在する**。すべての残高変動は「ウォレット間の複式記帳（振替）」に統一される |
| 立替精算の記帳 | 承認時に「部門ウォレット → 申請メンバーのウォレット」の振替として記帳（実出金はスコープ外） |
| 残高不足チェック | 申請時に警告表示、**承認時点の残高で最終判定**（不足なら承認不可）。マイナス残高は許容しない |
| 承認と記帳 | **承認と同時に自動記帳**（1 トランザクション）。「記帳は承認後にのみ」（GLOSSARY）の実装形 |
| 逆仕訳 | **逆仕訳も申請 → 承認を通る**。台帳から元エントリを指定して逆仕訳申請を作成し、checker の承認で記帳される。訂正だけが承認をバイパスする穴を作らない |
| 原資（予算配賦） | テナントごとに**準備金ウォレット**（会社の金庫）を 1 つ持つ。予算配賦は「準備金 → 部門」の**通常の振替**（admin が申請し、checker が承認）。準備金の初期残高のみテナント開設時の初期化エントリとして記帳される（唯一の承認外エントリ＝開設イベント） |

この決定によるワイヤー修正点: 台帳画面のボタン文言は「逆仕訳を**申請**」とする。
承認画面・申請一覧の種別には「逆仕訳」が現れ得る。

## 対応ビューポート方針（2026-07-20 確定）

デスクトップファースト（1280px 基準）。モバイル対応は本設計の対象外とし、
将来対応する場合は全画面一律ではなく「承認」画面（外出先からの承認ユースケース）
から縦切りで行う。

## 共通シェル（全画面）

- [ ] サイドバーナビ: ダッシュボード / 部門ウォレット / 振替・精算申請 / 承認 / 台帳 / 監査ログ / ロール管理（選択中状態を表示）
- [ ] テナント切替: ヘッダーにテナント名と切替メニュー（1 メンバーは複数テナントに所属し得る）。切替時は全データが切り替わることが視覚的に分かる
- [ ] ログイン中メンバー名とロールバッジの常時表示
- [ ] ロールにより非表示・無効化されるナビ項目の方針を明示（例: viewer は申請・承認が非活性）

## 1. 部門ウォレット

**目的**: テナント内の部門別ウォレットの残高と動きを一覧・詳細で把握する。

- [ ] ウォレット一覧: 部門名 / 残高（等幅数値・右揃え） / 今月の振替件数 / 最終更新
- [ ] 準備金ウォレットが「準備金」バッジ付きで一覧の先頭に表示される（予算配賦の原資）
- [ ] 残高は台帳エントリの集計値であることの表示（「残高は台帳から算出」の注記または導線）
- [ ] ウォレット詳細: 残高推移サマリー + 直近の台帳エントリ抜粋 + 台帳画面への導線
      （2026-07-21 判断: 詳細ビューはワイヤー対象外とし、実装フェーズの縦切りで設計する。
      当面は台帳画面のウォレットフィルタが代替導線）
- [ ] 状態: 通常 / データ 0 件（ウォレット未作成の空状態） / 読み込み中
- [ ] 権限差分: admin のみ「ウォレット作成」ボタンが見える。viewer は閲覧のみ

## 2. 振替・精算申請

**目的**: ウォレット間の振替、立替精算の申請を作成する（記帳は承認後）。

- [ ] 申請フォーム: 種別（振替 / 立替精算） / 振替元・振替先ウォレット / 金額 / 摘要 / 添付（立替精算の証憑想定・ダミー）
- [ ] 冪等キー: 申請作成時にクライアント生成の冪等キーを持つことを UI 上で表現（再送信・二重クリックでも申請が 1 件になる説明表示。開発者向け画面ではキー値の確認導線）
- [ ] 二重送信防止の状態表現: 送信中はボタン無効化 + 送信済み表示
- [ ] 自分の申請一覧: 状態バッジ（下書き / 承認待ち / 承認済み / 却下 / 取り下げ）付き
- [ ] 状態: 入力エラー（残高不足・同一ウォレット指定） / 送信中 / 送信済み / 0 件
- [ ] 権限差分: maker のみ作成可。checker は自分の担当分の閲覧導線。viewer は非活性

## 3. 承認（maker-checker）

**目的**: 承認者が申請を確認し、承認・却下する。記帳は承認後にのみ行われる。

- [ ] 承認待ち一覧: 申請日時 / 申請者 / 種別 / 金額 / 摘要（優先度順・古い順）
- [ ] 詳細パネル: 申請内容全項目 + 申請者情報 + 承認・却下ボタン + 却下理由入力
- [ ] maker-checker 分離の表現: 自分が作成した申請は一覧に出ない、または非活性 + 理由表示（「自分の申請は承認できません」）
- [ ] 承認・却下の確認ステップ（即時実行しない）
- [ ] 状態: 承認待ち 0 件（空状態） / 承認実行中 / 完了トースト
- [ ] 権限差分: checker のみ承認・却下可。admin でも maker-checker 分離は破れない

## 4. 台帳（append-only）

**目的**: 残高の正本である台帳エントリを閲覧する。訂正は逆仕訳のみ。

- [ ] エントリ一覧: 記帳日時 / エントリ ID / ウォレット / 借方・貸方 / 金額（等幅数値） / 摘要 / 関連申請への導線
- [ ] append-only の表現: 編集・削除ボタンが存在しない。「台帳は追記のみ。訂正は逆仕訳で行います」の注記
- [ ] 逆仕訳: 逆仕訳エントリは元エントリとの相互リンク + 逆仕訳バッジで区別
- [ ] 逆仕訳の作成導線: 権限者のみ「逆仕訳を作成」（元エントリを指定した追記操作であることが分かる UI）
- [ ] フィルタ: 期間 / ウォレット / 種別。集計行（表示範囲の合計）
- [ ] 状態: 0 件 / フィルタ結果 0 件 / 読み込み中
- [ ] 権限差分: 全ロール閲覧可（テナント内）。逆仕訳作成は checker または admin

## 5. 監査ログ

**目的**: 誰が・いつ・何をしたかを追跡する（申請・承認・ロール変更・ログイン失敗等）。

記録対象の基準（2026-07-20 確定）: **状態を変えた操作 + 認証イベント（ログイン失敗）** に限る。
テナント切替・画面閲覧・検索などの「何も変えない操作」は監査ログの対象外
（閲覧の追跡はアクセスログ＝インフラ層の領分であり、業務監査ログに混ぜない）。

- [ ] ログ一覧: 日時 / 実行者（メンバー） / 操作種別 / 対象 / 結果（成功・失敗）
- [ ] 記録対象の明示: 申請作成・承認・却下・逆仕訳・ロール変更・ログイン失敗を含むことが分かる操作種別フィルタ
- [ ] 変更系ログは変更前後の要約を展開表示できる
- [ ] ログ自体が改変不能であることの注記（閲覧専用・エクスポートのみ）
- [ ] 状態: 0 件 / フィルタ結果 0 件
- [ ] 権限差分: admin と viewer（監査）のみ閲覧可。maker / checker はナビに出さない

## 6. ロール管理

**目的**: テナント内メンバーのロールを付与・変更する。

- [ ] メンバー一覧: 名前 / メールの一部マスク表示 / 現在ロールバッジ / 最終アクティブ
- [ ] ロール変更 UI: 変更前 → 変更後の確認ステップ + 変更理由入力（監査ログに残る旨の表示）
- [ ] 最後の admin を降格できないガードの表現（無効化 + 理由）
- [ ] 招待導線（メール招待のダミー UI で可）
- [ ] 状態: メンバー 1 名のみ / 変更実行中 / 完了トースト
- [ ] 権限差分: admin のみ操作可。他ロールはこの画面自体に入れない

## ワイヤー完成時の適合確認

6 画面それぞれについて、上記チェックリストの全項目が満たされているかを確認し、
結果（画面 × チェック項目の充足表 + 未充足の理由）を devlog に記録する。

### 適合判定の深さ（2026-07-20 赤入れで確定）

- ワイヤーで描くのは各画面の**通常状態のみ**。空状態のワイヤー化は代表画面（台帳）のみ行う
- 空 / エラー / 読み込み / 実行中などの状態系チェック項目は、本仕様書の記述をもって充足とみなす
- 権限差分は「その画面の代表ロール視点」で 1 枚描き、他ロールの差分は注記で表現してよい
